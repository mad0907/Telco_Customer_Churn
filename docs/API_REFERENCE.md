# API Reference

Manual reference for every module and function in this repository, covering
what real `pydoc` HTML (`docs/pydoc/*.html`) can and cannot generate safely.
`pipeline_dev.py`, `modeling_dev.py`, and `churn_features.py` have no
import-time side effects, so their `pydoc` output is generated directly
(see `docs/pydoc/`, or regenerate with the command at the bottom of this
file). The remaining modules run real work at import time (writing a
notebook, rendering diagrams, writing a `.docx`, or launching a Streamlit
UI), so introspecting them via `pydoc` would trigger that work as a side
effect -- they are documented by hand below instead.

## Runtime / deliverable modules

### `src/churn_features.py`
Shared, side-effect-free cleaning and feature engineering, used by `app.py`
at inference time. Full HTML: `docs/pydoc/churn_features.html`.

- `clean(df)` -- coerces `TotalCharges` to numeric, fills the structural-zero
  rows (`tenure == 0`), normalizes `SeniorCitizen`, drops `customerID`, maps
  `Churn` to 0/1 if present.
- `engineer_features(df)` -- derives `num_add_on_services`,
  `avg_monthly_spend`, `tenure_bucket`.
- `prepare_for_scoring(raw_record: dict) -> pd.DataFrame` -- runs a single
  raw customer record through `clean()` and `engineer_features()`, raising
  `ValueError` if a required field is missing. This is the one function
  `app.py` actually calls.

### `app.py`
Streamlit prototype. Run with `streamlit run app.py`; see README.md.

- `load_model_and_metadata()` -- loads `models/churn_xgboost_pipeline.joblib`
  and `models/model_metadata.json`, cached per session. Raises
  `FileNotFoundError` with an instructive message if the notebook has not
  been run yet.
- `build_explainer(_model)` -- builds and caches a `shap.TreeExplainer` on
  the pipeline's classifier step.
- `assign_risk_tier(probability, metadata)` -- maps a probability to
  Low/Medium/High/Critical using the bins saved in `model_metadata.json`.
- `recommend_action(tier, top_drivers)` -- turns a tier and its SHAP
  drivers into a specific recommendation (leads with a contract/payment
  offer when either is a top driver, rather than a generic message).
- Module-level `EXAMPLE_PROFILES`, `CATEGORICAL_OPTIONS` -- form defaults
  and the two example customers in the dropdown.
- The rest of the file is Streamlit UI layout (form, columns, result
  display), not a library API.

### `deployment/score.py`
Azure ML managed online endpoint entry script. Not imported directly in
this repository (its `mlflow` dependency lives in `scoring_env.yml`, the
serving container's environment, not the local `requirements.txt`).

- `init()` -- endpoint entry point, called once per worker at container
  startup; loads the model into the module-global `model`.
- `run(raw_data: str)` -- endpoint entry point, called once per scoring
  request; validates, scores, and audit-logs each record in the payload.
- `_validate_payload(record)` -- guardrail: raises `SchemaValidationError`
  on a missing or out-of-range field, before the record reaches the model.
- `_hash_input(record)` -- SHA-256 hash of the canonicalized input, used as
  the ledger's input reference (see `deployment/governance_logging.md`).
- `_log_prediction_event(input_hash, prediction, probability)` -- writes
  the signed, immutable audit record; raises (fail-closed) if logging
  fails, so `run()` never returns a prediction it could not log.

## Notebook (`notebooks/telco_churn_analysis.ipynb`)

The notebook is generated by `src/build_notebook.py` and is the primary
analysis deliverable. Its structure (section numbers match the notebook's
own markdown headers) is documented in `docs/Telco_Churn_Writeup_and_Architecture.docx`
Part I; this reference covers the callable functions it defines internally,
since those are reused across cells:

- `load_raw(path)`, `clean(df)` -- same logic as `src/pipeline_dev.py`,
  defined inline so the notebook has no external file dependency.
- `engineer_features(df)`, `build_preprocessor(X, scale_numeric)` -- same
  logic as `src/modeling_dev.py`, defined inline for the same reason.
- `expected_cost(y_true, proba, threshold)` -- cost-matrix evaluation used
  throughout Section 9.
- `bootstrap_cost_distribution(y_true, proba, threshold, n_boot, seed)` --
  resamples the test set to produce a cost confidence interval (Section 9.3).
- `gain_table(y_true, proba, n_bins)` -- cumulative-gains computation used
  in the lift/gain chart (Section 9.4).
- `assign_risk_tier(proba)` -- same tiering logic persisted into
  `model_metadata.json` and reused by `app.py`.
- `explain_customer(row_idx, ...)` -- the per-customer decision-card
  function (Section 11.1); `app.py`'s `recommend_action()` is the same
  logic adapted for interactive use.

## Build tooling (`src/build_*.py`)

These scripts generate the deliverables above; they are not meant to be
imported as libraries (each runs its generation logic at import time), and
are documented here rather than via `pydoc` for that reason.

### `src/build_notebook.py`
Constructs `notebooks/telco_churn_analysis.ipynb` cell by cell via
`nbformat`. Two helpers: `md(text)` appends a markdown cell, `code(text)`
appends a code cell. Run: `python build_notebook.py` (writes the file;
does not execute it -- see README.md for the execute step).

### `src/build_diagrams.py`
Renders the three architecture diagrams as PNGs via matplotlib, rather
than Mermaid, so they display without a Mermaid-aware viewer. Helpers:
`box()`, `arrow()`, `label()`, `new_canvas()` -- small drawing primitives
for boxes, connecting arrows, and text labels on a matplotlib axes. Run:
`python build_diagrams.py`.

### `src/build_writeup_doc.py`
Constructs `docs/Telco_Churn_Writeup_and_Architecture.docx` via
`python-docx`. Helpers: `add_heading()`, `add_para()`, `add_rich_para()`
(mixed bold/plain runs), `add_bullets()`, `add_table()` (styled, zebra-
striped), `add_code_block()` (shaded monospace), `add_image()` (centered,
optional caption), `add_rule()`, `add_page_break()`. Numbers embedded in
this script (model metrics, lift, tier rates) were copied from the
executed notebook's output -- see the note in README.md about keeping them
in sync if the modeling code changes.

## Development / verification scripts (`src/pipeline_dev.py`, `src/modeling_dev.py`)

Not deliverables -- used to validate the cleaning and modeling logic before
it was transcribed into the notebook. Full HTML:
`docs/pydoc/pipeline_dev.html`, `docs/pydoc/modeling_dev.html`.

- `pipeline_dev.load_raw(path)`, `pipeline_dev.audit(df)`,
  `pipeline_dev.clean(df)` -- data loading, profiling, and cleaning.
- `modeling_dev.engineer_features(df)`, `modeling_dev.build_preprocessor(X, scale_numeric)` --
  feature engineering and the preprocessing `ColumnTransformer`.
- Both have a `main()` that runs end to end and prints results; guarded by
  `if __name__ == "__main__"`, so importing either module is side-effect-free.
